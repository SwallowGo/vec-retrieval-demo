定位中高级 Java 后端，考察：并发编程、队列、数据结构、算法、参数校验、业务异常、内存线程
安全存储，面向 AI 应用方向 Java 招聘。
一、核心需求
实现文本模拟向量化与向量检索微服务。
•
模拟 Embedding 向量化（不调用 LLM / Embedding API）
•
模拟向量化耗时任务，需用异步处理
•
支持文档入库、向量检索 Top‑N、文档元信息溯源统计
•
支持失效文档标记
•
需要保证多线程并发安全
关于模拟向量化的说明：
真实 Embedding 的特性是：相同文本输出向量稳定；语义相近文本向量接近。
此题主要考察文本向量化异步处理的工程实现，但其通常依赖于外部的模型api，因此选用一个能模
拟文本相似性的算法来实现，不要求真正实现语义近似。
二、功能描述
1. 文档入库（提交文档任务）
输入文档 ID、原始文本、渠道标识（可选），提交文档到服务；
向量化模拟存在 CPU 耗时，不能同步阻塞完成，提交任务后返回任务 ID，后台队列异步执行向量
化。
说明：向量化任务完成前，该文档不能参与向量检索。
2. 模拟向量化逻辑
•
向量固定维度：256 维 float 数组
•
同一文本多次向量化输出向量必须完全一致；空文本输出零向量。
3. 任务状态查询
根据任务 ID 查询向量化任务状态：排队中、处理中、完成、失败；任务完成后可以拿到文档信
息。
4. 向量检索功能
传入查询文本、topK、可选渠道过滤条件：
① 对查询文本执行同样向量化逻辑；
② 选用相似度算法，在已经完成向量化的有效文档库中计算相似度
③ 返回相似度降序 Top‑K 文档
约束：过滤已经标记失效的文档；支持按渠道筛选结果。检索为同步接口。
5. 文档管理能力
•
支持主动标记文档失效：失效文档不再参与检索
•
支持查询文档列表和详情（元信息：入库时间、任务完成时间、向量是否就绪、失效状态等）
•
支持查询文档向量化任务状态
6. 溯源 & 统计信息
每一篇文档记录元数据：渠道标识（不传默认 default ）、提交时间、向量化完成时间、被检索
命中次数；检索时会更新命中计数。
